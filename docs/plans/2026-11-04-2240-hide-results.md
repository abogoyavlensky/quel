# Hide Results Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ⌘J and a tab strip button hide and show the results pane, so the
editor can take the whole workspace; a run brings the results back.

**Tech Stack:** React + TypeScript, zustand store, react-resizable-panels 4,
lucide icons, Vitest, Playwright (server mode). No backend change.

---

## Design

### What the user gets

| Key (macOS / other) | What it does |
|---|---|
| ⌘J / Ctrl+J | Hides or shows the results pane |

- **Button.** A `PanelBottom` toggle in the editor tab strip, between the
  sidebar and row details toggles, so the three read left, bottom, right:
  history, `PanelLeft`, `PanelBottom`, `PanelRight`. It mirrors
  `SidebarToggle`: ghost `icon-sm`, `aria-label="Results"`, `aria-pressed`
  while the results show, `title="Results (⌘J)"`.
- **Command Palette.** "Hide Results" / "Show Results" in the View group,
  after the sidebar entry, with ⌘J and `keepsFocus`. It shows only with a
  loaded workspace, as the sidebar entry does.
- **No native menu item.** A toggle cannot take the double delivery that
  Run tolerates, the same reason as ⌘B and ⌘I.

⌘J is what VS Code uses to toggle its bottom panel, next to ⌘B for the
sidebar. Nothing else claims it: CodeMirror's keymaps bind no `j`, the app's
menu has no ⌘J accelerator, and Wails' edit menu role has no Jump to
Selection item. Chrome's Ctrl+J (downloads) in server mode is stopped by
the capture-phase listener's `preventDefault`; the e2e test checks that.

### State

`resultsHidden: boolean` in the store, in memory only, starting `false`,
like `rowDetails`. It is app-wide, not per tab, and resets on restart.
There are no new bridge handlers. A run shows the results again, so a saved
"hidden" would rarely survive a session; a restart that shows the results
costs one key press.

In `state/layout.ts`, next to the sidebar functions:

```ts
export function toggleResults(): void; // no-op without a tab strip
export function showResults(): void;   // sets resultsHidden: false
```

`toggleResults` follows `toggleSidebar`: it does nothing unless
`hasTabStrip`, and hiding with focus inside the results moves focus to the
editor. The results panel carries `data-quel-results` for that check.

### The panel

Drawn or left out, never collapsed, the rule `docs/DESIGN.md` already sets
for the sidebar and row details. In `AppShell.tsx`:

- The vertical group stays mounted. The handle and results panel render
  conditionally **after** the editor panel, so the editor is not remounted
  and keeps its focus and cursor.
- Both panels get ids (`editor`, `results`). The library keeps a layout per
  id set (`mutableState.layouts`), so a dragged split comes back on show.
- `defaultSize` moves from the editor to the results panel:
  `defaultSize="55"` on `results`, none on `editor`. The first split is
  unchanged. This is required: panels without a `defaultSize` share the
  remainder, so an editor with `defaultSize="45"` would get 45% when alone.

**What hiding loses:** the grid's scroll position and hand-set column
widths, which live in `ResultGrid`. Switching result tabs loses them today,
so this is an existing limit. The selected row lives in the store, so it
stays and the row details panel keeps showing it. An export in progress
finishes; it is a runner function, not tied to the footer.

### Bringing the results back

With the pane hidden there is no footer and no Messages tab, so a run
would give almost no feedback. The results show again whenever a run has
something to say:

- `runCurrent`: the not-connected refusal, whose banner lives in the pane.
- `runStatements`: the read-only refusal, whose message goes to Messages.
- `runStatements`: once the run is going ahead, after the confirm dialog.
  Hooked there rather than in `runCurrent`, so `rerunLost` is covered.

They stay hidden when nothing happens: an empty editor, a run in flight in
the tab, a declined confirm. Hiding during a run is honoured; the tab's
pulsing dot and the run button still show it runs. Focus stays in the
editor throughout, as for any run.

**⌘R while hidden.** `showsResult` is still true but no grid is mounted, so
`focusResult` shows the results and focuses on the next tick. That covers
the key and the palette's Focus Result, which both call it. Where ⌘R does
nothing today (Messages, a result with no rows), it still does nothing, and
the pane stays hidden.

### Keys

`shortcutOf` gains `{ kind: "resultsPane" }` for `j`, matched like ⌘B
(platform modifier, no Shift, no Alt): ⌘J on macOS, Ctrl+J elsewhere, and
not Ctrl+J on macOS. The name keeps it apart from ⌘R's
`{ kind: "result" }`. `toggleResultsKey()` in `palette.ts` applies the
`modalOpen` guard. `keys.ts` gains `RESULTS_PANE_KEY`, kept apart from
`RESULT_KEY` the same way.
