# No Status Bar Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The bottom status bar goes away. Each thing it said moves to
the part of the window it describes: connection state to the top strip,
run state to the results footer, notices to toasts, and the Update
button to the top strip in the accent colour.

**Tech Stack:** React + TypeScript, zustand store, sonner (through
`lib/notify.ts`), lucide icons, Tailwind, Vitest, Playwright (server mode).
Frontend only: no backend change.

---

## Design

### Why

The status bar is 36px of chrome that mostly repeats what is already
on screen. The connection is named in the top strip, the running tab has
a dot, Run turns into Stop, and toasts already exist. The rest is said
far from where the user is looking. The results panel gets those 36px
back.

### Where each piece goes

`StatusBar.tsx` shows four things today. After this change:

| Today (status bar) | After |
|---|---|
| "No connection" | The top strip says "Quel" (as today) |
| "Not connected", "Connecting…", "Disconnecting…" | Words in the top strip's pill, after the engine |
| "Ready" | Nothing: no words in the pill means connected |
| "Running… 12s", "Canceling…" | The results footer: words on the left, the time on the right |
| Notices (`store.notice`) | Toasts through `notify` |
| Update button | Top strip, right end, solid accent |

### The top strip (`TitleBar.tsx`)

- **The pill** gains the connection's state as words, in the muted colour,
  after the engine label: `● Prod  PostgreSQL · Not connected`. The words
  are "Not connected", "Connecting…" and "Disconnecting…"; a connected
  profile shows none. The name keeps its tag ink colour, and the words
  never take it. When the workspace is not loaded yet (`w` undefined), the
  status counts as disconnected, as `StatusBar` does today.
- **The Update button** sits at the right end of the strip:
  `Button` with the default variant (solid `bg-primary`, white text) and
  `size="xs"`, absolutely placed (`absolute right-2.5`, the header becomes
  `relative`). It carries `[--wails-draggable:no-drag]` so a click on it
  is a click, not a window drag. Its label comes from
  `updateLabel(s.update)` ("Update", "Updating 42%", "Restart to Update",
  "Update failed"); idle draws nothing. Clicking it opens the update
  dialog, as the status bar button does today.
- **Padding.** The header's `px-24` becomes `px-40` on both sides, so the
  centred pill never runs under the button ("Restart to Update" is about
  140px wide with its margin). Symmetric padding keeps the pill centred.
  At the minimum window width (720px) the name truncates, as it does now.
- **Unchanged:** 36px height, `:mac-title-bar :hidden`, the tag tint, the
  traffic lights' place.

The solid accent breaks the "soft indigo" habit of Run and the result
chips on purpose: it is the one thing in the window that asks for action,
and it shows only while an update is pending. A soft tint gets lost on a
red or orange tag tint.

### The results footer

Today the footer lives in `ResultGrid` and exists only while a result's
grid shows. During a run there is usually no grid: `runStatements` drops
the unpinned results and shows Messages (`runner.ts`, the `updateTab`
at the start of a run). So the footer moves up a level: a new
`ResultFooter` component, drawn by `ResultTabs` below the content area,
and `ResultGrid` loses its own footer.

It is drawn when either holds:

1. the tab is busy: `isRunning(tab)` has been true for 300ms (the same
   delay as Stop, so a quick query never flashes "Running…");
2. the active view is a result (`current` in `ResultTabs`).

Otherwise (Messages or the empty hint, nothing running) there is no
footer, as today.

| State | Left | Right |
|---|---|---|
| Busy | spinner + "Running…" (or "Canceling…" when `tab.stopping`) | the elapsed time, ticking ("12s", `formatElapsed`; nothing under 1s) |
| A result, not busy | the rows text (today's `footer(result)` in `ResultGrid`) | Export menu + "N ms" |

- While busy with a kept (pinned) result active, the run's words and time
  replace that result's rows and time, and Export hides. The run matters
  more while it lasts.
- A page load ("loading more…") is not a run: `isRunning` is already false
  while a result is fetching, so the rows text shows as today.
- When a run ends, the active view moves to its last result (the runner
  already does this), so "Running… 12s" becomes "500 rows · 12,345 ms" in
  place.
- **Accessibility.** The footer is `role="group"` with
  `aria-label="Result footer"`. Its left slot is `role="status"` (a
  polite live region, replacing today's `aria-live="polite"`), so screen
  readers hear "Running…" and then the row count. With the status bar
  gone it is the page's only `role="status"`.
- **Look:** 36px, `border-t`, `px-3.5 text-xs text-muted-foreground`, the
  same as today's grid footer. The words are `text-foreground`. The
  spinner is lucide `LoaderCircle` at `size-3.5 animate-spin`.

No dimming of the previous result: the mockup showed it, but the old
result is not on screen during a run (see above), and a kept result is
not out of date.

`useDelayed` moves from `RunButton.tsx` to `frontend/src/lib/useDelayed.ts`,
shared by `RunButton` and `ResultFooter`. Like `RunButton`, the footer is
keyed by tab, so switching to another running tab starts the delay over. The `Elapsed` ticker moves from
`StatusBar.tsx` into `ResultFooter.tsx`.

### Notices become toasts

`store.notice` and everything that reads or clears it go away. Each
notice becomes a `notify` call:

| Where | Today | After |
|---|---|---|
| `runner.closeTab` on a pinned tab | notice "Unpin the tab to close it." | `notify.info("Unpin the tab to close it.", { id: "unpin-to-close" })` |
| `runner.togglePin` unpinning | clears that notice | `notify.dismiss("unpin-to-close")` |
| `runner.closeTab` failure | notice "Could not close the tab: …" | `notify.error(...)` with the same text |
| `runner.reopenTab` failure | notice "Could not reopen the tab: …" | `notify.error(...)` with the same text |
| `persist` save failure | notice "Could not save tabs: …" until a save works | `notify.error(SAVE_FAILED + err, { id: \`save-failed-${profileId}\`, duration: Infinity })` |
| `persist` save success | clears the notice | `notify.dismiss(\`save-failed-${profileId}\`)`, only if that profile had failed (`saveErrors.has`) |
| `RowDetails` copy failure | notice "Could not copy." | `notify.error("Could not copy.")` |
| `selectProfile`, `connectProfile`, `deleteProfile`, editor edits (`clearNotice`) | clear the notice | nothing: toasts time out or are closed |

- **The save failure stays up** (`duration: Infinity`) until a save of
  that profile works, as the status bar notice did. Its id is per profile,
  so a good save of profile B does not hide profile A's failure (today's
  notice had that bug). The user can close it; the next failed save brings
  it back. The same id means a retry replaces it rather than stacking.
- `NoticeOptions` in `lib/notify.ts` gains `duration?: number`, passed
  through to sonner.
- `clearNotice` in `runner.ts` and the editor's update listener that calls
  it (`editor/setup.ts`) are deleted.

### Unchanged

The top strip's height and the macOS title bar preset; the sidebar; the
Run/Stop button; the running dot on editor tabs; the `NotConnected`
states in the results; the update dialog itself.

### Testing

- **Unit (Vitest):** a small pure module `state/status.ts` with
  `connectionWords(status)` and `runWords(tab)`, tested in
  `state/status.test.ts`. `runner.test.ts` and `persist.test.ts` switch
  their notice assertions to the mocked `notify` (`runner.test.ts` already
  mocks it as `toasts`; `persist.test.ts` adds the same mock).
  `notify.test.ts` covers `duration`.
- **E2E (Playwright):** the 12 `getByRole("status")` assertions and the
  `contentinfo` ones change targets (Task 6). Two helpers in
  `e2e/connect.ts` replace "Ready" / "Not connected":
  - `expectConnected(page)`: the banner contains neither "Not connected"
    nor "Connecting…". Before a connect the banner says "Not connected",
    so this cannot pass early.
  - `expectNotConnected(page)`: the banner contains "Not connected".
- **By hand:** server mode in a browser, as in Task 7.
