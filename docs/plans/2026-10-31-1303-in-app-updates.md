# In-App Updates Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Quel finds a newer release on its own and shows an "Update" button. The button opens a dialog with three choices: download, verify and install the release, then restart into it; skip that version; or decide later.

**Tech Stack:** Wails v3.0.0's `pkg/updater` (GitHub Releases provider, bundle swap, restart helper), exposed through letgo-packages' `wails` package. On the Quel side: a let-go component and handlers, and a React status-bar button and dialog (shadcn `Dialog`, zustand, sonner).

---

## Design

### Why the Wails updater

Wails v3.0.0, which Quel already links, ships `pkg/updater`
(`~/go/pkg/mod/github.com/wailsapp/wails/v3@v3.0.0/pkg/updater`). It
already does the parts that are hard to get right:

- a GitHub Releases provider. Its default asset matcher picks
  `quel_X.Y.Z_darwin_arm64.zip` (the name contains `darwin` and `arm64`).
  `ChecksumAsset: "checksums.txt"` makes it check the download's SHA-256.
- a streaming download with `wails:updater:download-progress` events, which
  reach the frontend through `app.Event`.
- unzipping into a staging directory and swapping the `.app` atomically,
  with a backup and a rollback.
- a restart helper: the same binary, re-executed with `WAILS_UPDATER_HELPER*`
  environment variables. It waits for the old process to exit, swaps the
  bundle, runs `codesign --verify` on the result and starts the new app with
  `open -n`.

What it lacks, and what this plan adds:

1. **A let-go surface.** The `wails` package exposes none of it. Under the
   project rule "what let-go cannot reach goes upstream", that is a new
   `updater.go` in `wails/shim` and a veneer in `wails/src/wails/core.lg`,
   released as `wails-v0.6.0`.
2. **A signer check.** Wails' codesign check only confirms that a bundle's
   signature is intact. It tolerates an unsigned bundle, and it accepts a
   bundle signed by anyone else. The shim adds the check Sparkle makes:
   before an update is installed, the staged `.app` must satisfy the
   running app's *designated requirement* (`codesign -d -r-`). That ties
   every update to Quel's Developer ID team. Without it, the trust chain
   would be "HTTPS to GitHub, plus a checksum from the same release page".
3. **Persistent skip.** `Updater.SkipVersion` only lives in memory. Quel
   keeps the skipped version in its `settings` table and decides itself
   what to show.
4. **The helper must start before Quel does.** Wails enters helper mode
   inside `application.New`, and Quel calls that from integrant *after*
   `quel.store/db` has opened SQLite and run migrations. The shim's Go
   `init()` therefore calls `updater.HandleHelperMode()` first, so a helper
   process swaps the bundle and exits before any let-go code runs.

### Upstream: the `wails` package (letgo-packages, `wails-v0.6.0`)

Go shim `wails/shim/updater.go`, registered in `shim.go`'s `init()`:

| Shim fn | Does |
|---|---|
| `UpdaterInit(app, opts)` | `app.Updater.Init` with `CurrentVersion`, a single `github.New` provider (`Repository`, `ChecksumAsset`, `BaseURL` when given), `Window: updater.WindowNone`, and no `CheckInterval`: the app decides when to check. A second call is a no-op that returns nil, and the first config wins (`ErrAlreadyConfigured` is swallowed). `application.New` hands back the existing global app, so restarting the system from the nREPL (`stop!`, then `start!`) reaches `Init` again, and an error there would fail the whole system. |
| `UpdaterCheck(app)` | `Check` with a 20 s timeout. Returns the release as a map, or nil when the app is up to date. |
| `UpdaterDownload(app)` | `DownloadAndInstall` (blocks; progress goes out as events), then the signer check on `DownloadedPath()`. If the check fails it removes the staged directory and returns an error. The check runs on darwin only; elsewhere it is skipped, since `UpdaterCanInstall` is false there anyway. |
| `UpdaterRestart(app)` | `Restart`: the helper starts, then the app quits. |
| `UpdaterCanInstall()` | True only if all of these hold: darwin; the running executable is inside a `.app`; that bundle's designated requirement can be read and contains `anchor apple generic` (an Apple-issued certificate, not ad hoc); and the bundle's parent directory is writable. Otherwise it returns false and a reason string. |

The release map that crosses into let-go (string keys, as the bridge
already lowers them):

```clojure
{:version "0.3.0"           ; Release.Version, no "v"
 :name "Quel 0.3.0"         ; Release.Name
 :url "https://github.com/abogoyavlensky/quel/releases/tag/v0.3.0"
                            ; Metadata["github.release.htmlURL"]
 :published-at "2026-11-20T10:00:00Z"
 :size 41234567}            ; Artifact.Size
```

`init()` gains `updater.HandleHelperMode()` as its first statement, with a
comment that explains point 4 above.

Veneer in `wails/src/wails/core.lg`: `updater-init!`, `check-update`,
`download-update!`, `restart-to-update!` and `can-install-update`. The last
returns `{:ok bool :reason str}`.

The signer check, Go side:

1. Run `codesign -d -r- <running bundle>` and take the text after
   `designated => ` (codesign may write it to stdout or stderr; read both).
2. Run `codesign --verify --deep --strict -R=<"=" + requirement> <staged .app>`.
   As Go argv: `exec.CommandContext(ctx, "codesign", "--verify", "--deep",
   "--strict", "-R", "="+requirement, stagedApp)`. The leading `=` makes
   codesign read the requirement as text, not as a file path.
3. A non-zero exit is an error that carries codesign's output.

`DownloadedPath()` may point at the extracted `.app` or at its parent
directory. Check what `maybeExtractInto` returns, and resolve to the single
`*.app` inside when needed.

`maybeExtractInto` refuses an archive with more than one top-level entry.
`sign-macos.sh` zips with `ditto -c -k --sequesterRsrc --keepParent`, which
would add a top-level `__MACOSX/` if the bundle carried extended
attributes. The v0.1.0 zip has `Quel.app` as its only top-level entry (that
was checked), but nothing keeps it that way. Task 10 therefore makes the
release fail when the zip has any other top-level entry.

### Quel: the version it runs

The binary does not know its version today: `VERSION` only reaches
`Info.plist`. Add `src/quel/version.lg` with `(def version "0.1.0")`, and a
test that fails when it differs from the trimmed `VERSION` file. CI runs
that test on the tagged commit, so a release cannot ship with the two out of
step. `docs/RELEASE.md`'s bump step names both files.

### Quel: backend

New namespace `quel.updates`, an integrant component
`:quel.updates/updater` with `{:app (ig/ref :quel.shell/app) :store (ig/ref
:quel.store/db)}` plus its config:

- `:enabled?`: `(not= "off" (os/getenv "QUEL_UPDATES"))`.
- `:base-url`: `QUEL_UPDATES_URL` when it is not blank (use `str/blank?`;
  `os/getenv` returns `""` for an unset variable). Otherwise nil, meaning
  api.github.com.
- `:repository "abogoyavlensky/quel"` and `:version quel.version/version`.

When enabled, `init-key` calls `w/updater-init!`. It returns the env map
either way.

Handlers in `quel.api`, registered by var like the rest:

| Handler | Returns |
|---|---|
| `check-update` | `{:current "0.2.0" :enabled true :can-install true :reason nil :release {...} :skipped false}`. `:release` is nil when up to date. When disabled it is `{:current … :enabled false}` and nothing goes over the network. A failed check throws, which rejects the promise. |
| `skip-update` (version) | Stores `update-skipped` in `settings` (delete, then insert, like `workspace/select-profile!`). Returns `{:ok true}`. |
| `download-update` | Blocks until the update is staged and verified. Returns `{:ok true}`, or throws with the reason. |
| `restart-to-update` | Calls `w/restart-to-update!`. Quel's normal shutdown (`:on-shutdown` → `system/stop!`) cancels queries and closes sessions. |

`:skipped` is true when the stored skipped version equals the release's
version. A newer release clears it by not matching, as in VS Code. The
frontend's automatic check hides a skipped release; "Check for Updates…"
shows it anyway.

Menu: a new `Help` menu with `Check for Updates…`, which emits
`menu:check-updates` through `emitter` in `quel.menu`. The app menu would
be the natural place, but the wails shim builds `{:role :app-menu}` with
`AddRole` (`wails/shim/menu.go`), so that menu takes no custom items. The
Help menu is where it fits.

### Quel: frontend

A store slice `update` in `frontend/src/state/store.ts`, with the logic in
`frontend/src/state/updates.ts`:

```ts
type UpdateState =
  | { phase: "idle" }
  | { phase: "available"; info: UpdateInfo }
  | { phase: "downloading"; info: UpdateInfo; written: number; total: number }
  | { phase: "ready"; info: UpdateInfo; saveError?: string }
  | { phase: "restarting"; info: UpdateInfo }
  | { phase: "error"; info: UpdateInfo; message: string };
// UpdateInfo = check-update's reply with release non-null.
```

- **When it checks.** Once, 10 s after the app mounts, then every 6 hours.
  The automatic check fails silently (`console.warn`) and ignores a skipped
  release. A manual check (`menu:check-updates`) shows the dialog for
  anything it finds, skipped or not. Otherwise it toasts "Quel X is the
  latest version.", or the error, or "Update checks are off." when
  disabled.
- **Status bar.** At the right end of `StatusBar.tsx`, a small button that
  depends on the phase: available → "Update"; downloading → "Updating 42%";
  ready → "Restart to Update"; error → "Update failed". Idle shows nothing.
  Clicking it opens the dialog. It goes in the status bar, not the top
  strip, because the top strip is the window's drag area and takes the
  connection's colour tag.
- **Dialog** `frontend/src/components/UpdateDialog.tsx` (shadcn `Dialog`):
  - Title "Update Quel". Text: "Quel 0.3.0 is available. You have 0.2.0."
    A "What's new" link opens the release page.
  - If `can-install`: the buttons are "Skip This Version", "Later" and
    "Update" (primary). Update starts `download-update`. The dialog shows a
    progress bar from `wails:updater:download-progress` (`written`/`total`;
    read the `Progress` struct in `pkg/updater/types.go` for the field
    names), then "Restart Now". The dialog can close while the download
    runs; the button in the status bar keeps the progress.
  - If not `can-install` (dev or server mode, an ad-hoc build, a bundle
    that can't be written): the text says it can't update itself here and
    shows `brew upgrade --cask quel` with a Copy button
    (`lib/clipboard.ts`). The buttons are "Skip This Version", "Later" and
    "Open Release Page".
  - Before "Restart Now": if any workspace is connected, add "Running
    queries are canceled and open transactions rolled back." Restart flushes
    the saved tabs and waits for them (see Task 7), then calls
    `restart-to-update`. If a save failed, it does not restart. The dialog
    says "Could not save your tabs: <message>" and offers "Restart Anyway".
  - Error phase: the message, plus "Try Again" (download again) and "Open
    Release Page".
- **Opening links.** A new `lib/browser.ts` mirrors `clipboard.ts`: it tries
  `Browser.OpenURL` from `@wailsio/runtime` and falls back to
  `window.open(url, "_blank")` (server mode).

### Homebrew

`scripts/generate-cask.sh` adds `auto_updates true`. Without it, `brew
upgrade` would treat an app that updated itself as outdated and install the
same version over it. With it, plain `brew upgrade` skips Quel, while `brew
upgrade --cask quel` still upgrades it when named. People on 0.1.0 have no
updater, and the cask that adds `auto_updates` stops plain `brew upgrade`
from moving them. The 0.2.0 release notes and the README therefore tell
them to run `brew upgrade --cask quel` once.

### Test and server-mode runs never reach GitHub

`scripts/server-mode.sh` exports `QUEL_UPDATES="${QUEL_UPDATES:-off}"` and
passes `QUEL_UPDATES_URL` through to the app. Smoke runs keep checks off.
`scripts/e2e.sh` starts a stub GitHub (a small Python `http.server` script,
`frontend/e2e/fixtures/github-stub.py`) on a free port. It serves
`/repos/abogoyavlensky/quel/releases/latest`, with a release `v99.0.0` and
assets whose names match the runner's platform: `quel_99.0.0_linux_amd64.zip`
plus `checksums.txt`, and `darwin`/`arm64` on a Mac. Then e2e.sh runs the
app with `QUEL_UPDATES=on QUEL_UPDATES_URL=<stub>`. Backend tests build the
component with `:enabled? false`, or point it at a let-go `http/serve` stub.
AGENTS.md gets one rule line about this.

### What is not tested automatically

The download, swap and restart need a Developer ID-signed `.app`, so they
run on the Mac by hand (Task 11). The tests do cover: the release map and
`can-install` on Linux (the upstream package's server-mode tests, against a
stub provider server); `download-update` staging a zip and rejecting a bad
checksum; and Quel's handlers, the skip logic, the frontend phases and the
dialog through to the not-installable path in e2e.

### Out of scope

Background or automatic downloads, release notes inside the dialog (the
link covers them), a setting to turn checks off (`QUEL_UPDATES=off`
exists; add a toggle if anyone asks), delta updates, signed appcasts or an
EdDSA key, and Intel builds.

## Part 2: Quel

> Deviation: every shim fn returns `(vm.Value, error)`. A Go fn that returns a bare `error` hands the error to let-go as a value instead of throwing, so the first version's failed downloads looked like successes.
> Deviation: the checksum requirement lives in a wrapper around the GitHub provider (`digestRequired`). Wails' provider installs with no digest check when `checksums.txt` is missing or lacks the asset's line, and a refusal in the shim after `Check` would have left that release pending. Download also takes only what the last check returned (`offered`), and one lock covers check, download and the restart handoff (codex review).
> Deviation: on macOS the download test expects the signer error; the test runtime is no `.app`.
> Done: letgo-packages PR #16 merged (`627554e`), tag `wails-v0.6.0` pushed (the user authorized it).
