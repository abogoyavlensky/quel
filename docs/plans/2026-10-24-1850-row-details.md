# Row Details Implementation Plan

**Status: completed**

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Select a row in a result and read all its values in a read-only panel on the right of the window, with JSON values formatted and highlighted, and a copy button per value. Also drop the Connect button from the status bar.

**Tech Stack:** React 19, TypeScript, Tailwind v4, shadcn, zustand, TanStack Virtual, react-resizable-panels v4, `@lezer/json` + `@lezer/highlight` (new dependency: `@lezer/json`), Vitest, Playwright. Frontend only.

---

## Design

### Where this starts

The result grid (`frontend/src/grid/ResultGrid.tsx`) has no selection:
rows only highlight on hover, the grid takes no focus and no keys. Long
values are cut to one line in the grid (`grid/format.ts`, `MAX_CHARS`,
newlines as `↵`), and nothing in the app copies to the clipboard yet.
Rows in the store hold the full values (`ResultTab.rows`).

JSON reaches the frontend as a string. Postgres types the column
`JSON`/`JSONB`; Redshift's `SUPER` is typed too; in SQLite a JSON value is
plain `TEXT` (or an expression with no type) unless the column was
declared `JSON`.

Cut a branch `row-details` from master.

### Behaviour

- **Selecting.** A single click on a row selects it (a highlighted
  background, `aria-selected`). The grid becomes focusable
  (`tabIndex={0}`); while it has focus, ↑/↓ move the selection by one row
  and scroll it into view. ↓ with nothing selected selects the first row.
  The selection belongs to the result (`ResultTab.selectedRow`), in memory
  only: each result tab keeps its own, and a new run makes new results, so
  it clears. A pinned result keeps its selection. Paging in more rows
  leaves it alone.
- **Opening.** The panel's open state is app-wide (`AppState.rowDetails`,
  in memory, closed at launch). Three ways to change it:
  - a toggle button with a "panel right" icon at the right end of the
    editor tab bar, next to the recently-closed-tabs button;
  - `⌘I` / `Ctrl+I`, from anywhere in the window;
  - a double-click on a row selects it and opens the panel (never closes).
  A single click never opens the panel: it stays closed while you click
  around until you ask for it.
- **Following.** While open, the panel shows the active result's selected
  row and follows every change of selection, result tab, editor tab or
  profile.
- **Empty.** With no result active (the Messages tab, no tab) or no row
  selected, the panel shows a quiet hint: "Select a row to see its
  values."

### The panel

A third panel in the window's outer horizontal `ResizablePanelGroup`
(`components/AppShell.tsx`), after the workspace panel, rendered only
while open: full height above the status bar, default 25% of the width,
min 260 px, resizable through the usual handle.

```
┌ Row 12 of 500 ─────────── [{} copy row] [×] ┐
│ [Filter columns…]                            │
│ id                       integer       [⧉]   │
│ 12                                           │
│ email                    text          [⧉]   │
│ ann@example.com                              │
│ prefs                    jsonb         [⧉]   │
│ {                                            │
│   "theme": "dark",                           │
│   "limits": [1, 2.50]                        │
│ }                                            │
│ deleted_at               timestamptz   [⧉]   │
│ NULL                                         │
└──────────────────────────────────────────────┘
```

- An `<aside aria-label="Row details">`. Header: "Row N of M" (M is the
  loaded row count), a "Copy row as JSON" button, a close button. Under
  it a filter input ("Filter columns"): case-insensitive substring match
  on column names only; it is component state and survives row changes.
- One block per column, in column order: the name, its type in lowercase
  and muted (as in the grid header), and a copy button that shows on
  hover or focus of the block. The value below in monospace, wrapping
  (`whitespace-pre-wrap break-words`), real line breaks. NULL reads
  `NULL`, muted and italic, as in the grid. Numbers and booleans as their
  text.
- The list scrolls inside the panel; the header and filter stay put.

### JSON

A value is shown as JSON when it is a string and either:

- its column type is `JSON`, `JSONB` or `SUPER` (case-insensitive,
  exact; Postgres arrays like `_JSONB` are not), or
- the profile's engine is `sqlite` and the text, after leading
  whitespace, starts with `{` or `[`.

Postgres `text` columns holding JSON are not sniffed: agreed scope.

Then:

1. **Size cap.** Above `MAX_JSON_CHARS` (256 KiB) the value is shown as
   plain text, unformatted and unhighlighted, so one huge document cannot
   freeze the panel.
2. **Validation.** `JSON.parse` in a try. A value that does not parse is
   shown as plain text. The parsed result is thrown away: it is only a
   check.
3. **Formatting** by re-indenting the *original text*, never by
   `JSON.stringify(JSON.parse(v))`, which rounds big integers
   (`12345678901234567890`) and rewrites numbers (`1.10` → `1.1`).
   `reindent(text)` walks the characters of a valid JSON text:
   - a string (from `"` to the matching unescaped `"`, honouring `\\`
     and `\"`) is copied verbatim;
   - whitespace outside strings is dropped;
   - `{` / `[` opens: if the next non-whitespace character is the matching
     `}` / `]`, emit `{}` / `[]` and skip it; else emit the bracket, a
     newline, and indent one level deeper (2 spaces);
   - `}` / `]` closes: newline, one level shallower, the bracket;
   - `,` emits `,` then a newline at the current level;
   - `:` emits `: ` (a colon and one space);
   - any other run (numbers, `true`, `false`, `null`) is copied verbatim.
   A scalar JSON value (`"x"`, `42`) comes out unchanged.
   The output is capped too: indentation grows with depth, so a deeply
   nested value under the input cap (`[[[[…]]]]` 100,000 deep) would
   expand to gigabytes. `reindent` stops and returns null once its output
   passes `MAX_FORMATTED_CHARS` (1 MiB), and the value shows as plain
   text.
4. **Highlighting** with `@lezer/json`'s `parser` and `@lezer/highlight`'s
   `highlightCode`, into React spans, through a `tagHighlighter` that maps
   tags to the editor's colour variables (`index.css`), so JSON follows
   light and dark like the SQL editor:

   | lezer tag | class |
   |---|---|
   | `t.propertyName` | `text-(--sql-keyword)` |
   | `t.string` | `text-(--sql-string)` |
   | `t.number`, `t.bool`, `t.null` | `text-(--sql-number)` |
   | `t.brace`, `t.squareBracket`, `t.separator`, `t.punctuation` | `text-muted-foreground` |

   (Check the tags in `node_modules/@lezer/json/dist/index.js`'s
   `styleTags` call when writing the table.)

### Copying

- **A value:** the value exactly as stored: the cell string itself
  (never the reformatted JSON), or `String(cell)` for a number or
  boolean. The button is disabled for NULL: copying `""` would blur NULL
  and the empty string.
- **The row:** `rowAsJson(columns, row)`: a JSON object, column name to
  cell, `JSON.stringify(obj, null, 2)`. Cells go in as they are (big
  integers and decimals are already strings from `quel.cells`, JSON
  values stay strings), so nothing is rounded. A repeated column name
  (`select a.id, b.id`) gets a suffix: the second `id` becomes `id_2`,
  the third `id_3`, skipping any suffix already taken.
- **How:** `copyText(text)` tries `navigator.clipboard.writeText`, and
  if that throws, `Clipboard.SetText` from `@wailsio/runtime`. On
  success the button's icon turns into a check for 1.5 s. If both fail,
  the status bar notice says "Could not copy."

### Keys

`⌘I` is not put in the native menu (`src/quel/menu.lg`). A toggle cannot
take the double delivery that `Run` tolerates (native menu plus the
editor's keymap), and CodeMirror's default keymap binds `Mod-i`
(`selectParentSyntax`) and would swallow it in the editor. Instead, a
`keydown` listener on `window` in the **capture** phase (`App.tsx`)
handles Mod+I (`metaKey` on macOS, `ctrlKey` elsewhere; no Shift or Alt;
`e.key.toLowerCase() === "i"`): it calls `preventDefault` and
`stopPropagation` and toggles the panel, so CodeMirror never sees it. It
works the same in the native app, server mode and Playwright. The toggle
button's title shows the key (`ROW_KEY` in `components/keys.ts`).

### The status bar's Connect button

Removed. The connection mark and "Not connected" already say the state,
and the profile row's plug button and the structure panel's Connect do
the job. The status bar comment, the layout sketch in `docs/DESIGN.md`
and the workspaces e2e spec that clicked it change with it.

### Out of scope

- Editing values. The panel is read-only.
- Cell selection and the grid context menus ("copy cell / row / column",
  DESIGN.md): milestone 4. Moving from a row cursor to a cell cursor
  later adds a column to `selectedRow`'s state; nothing here is thrown
  away.
- A CodeMirror view per value (folding, search), a collapsible JSON
  tree, sniffing JSON in Postgres text columns.
- Binary values: still "(binary)" (`docs/backlog/bytea-preview.md`).
- Remembering the panel's open state or width across launches.

### Testing

- Vitest: `reindent` and `jsonText` (formatting decisions, size cap,
  invalid JSON, number preservation), `rowAsJson` (duplicates), the
  store actions (select, toggle, open, selection cleared by a new run).
- Playwright (`lgx e2e`, server mode, SQLite fixture): select a row by
  click and arrows, the panel by the button, the key and a double-click,
  JSON formatted with `1.10` intact, copy a value and the row, NULL's
  copy disabled, the filter. The workspaces spec connects from the
  sidebar instead of the status bar.
