# Redesign Implementation Plan

**Status: completed**

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Quel a clear, light, consistent look. That means bigger
defaults, an indigo accent, editor tabs as a segmented track and result
tabs as chips, and a top strip that names the selected connection in its
tag colour. The strip uses a hidden macOS title bar, which letgo-packages'
`wails` package first has to expose. The UX and the places of elements do
not change: this is the visual layer only.

**Tech Stack:** letgo-packages `wails` (Go shim over Wails v3.0.0, let-go
veneer, `lgx test` in server mode). Quel frontend: React 19, TypeScript,
Tailwind v4, shadcn, CodeMirror 6, TanStack Virtual, Vitest, Playwright.
No new dependencies.

## Design

### The visual reference

`docs/plans/2026-10-30-2129-redesign-prototype.html` is the approved
prototype. It is a self-contained page. Open it in a browser at
`?style=a&id=header&sel=1`, which is layout A with the name in the header
and a red-tagged connection. Click the connections in its sidebar to see
an untagged connection, an orange tag and a green tag. The other toggles
show rejected options. This plan gives the exact values; the page shows
how they look together.

### What it looks like

**Layout A, flat.** The workspace (tabs, editor, results) is white. The
sidebar, the top strip and the status bar share one light grey,
`--chrome`. Hairlines (`--border`) separate them. There are no rounded
panels or cards. Rounding lives in small pieces: the tab track, the result
chips, the statement block, the Run button, the selected sidebar row and
the connection pill in the strip.

**Colour.** The neutrals move from pure grey (chroma 0) to a faintly cool
grey (hue 265). One accent, indigo, becomes `--primary`. It marks
selection, focus, the caret, the active result chip, the selected grid
row, the selected sidebar connection, default buttons and the Run button,
which is the only filled accent button in the workspace. Tag colours keep
their dots (`ConnMark`) in the sidebar and in the strip, as today. As a
surface tint and as name text, a tag colour appears in one place only:
the top strip. Selection, focus and the other accents never take the tag
colour.

**The top strip (header).** It is a 40px band across the full window
width, above the sidebar and the workspace. It shows the selected
connection in the centre: its `ConnMark`, its name (medium weight) and its
engine (muted). With no profile selected, it shows "Quel". A profile with
a colour tag tints the strip: the background is the tag mixed 12% into
`--chrome`, and the bottom hairline takes the tag at about 25%. The name
sits in a white pill with a faint tag-coloured ring, written in that tag's
*ink* colour (below). An untagged profile leaves the strip neutral.

The strip is the drag area for the window (`--wails-draggable: drag`).
On macOS the window uses Wails' hidden-inset title bar: the traffic lights
float over the strip's left end and the page draws under them. The strip
reserves no room for them, because its content is centred. That also
settles fullscreen: when the lights disappear, nothing needs to move, so
no fullscreen event is wired. Server mode, the e2e tests and a Linux build
have no traffic lights, and the strip looks complete without them. A
Linux desktop build keeps its native title bar above the strip; Quel
ships for macOS only.

**Tag ink for readable names.** Tag colours are tuned as dots. Yellow at
`oklch(0.8 …)` is unreadable as text on a light tint. Each tag therefore
gets an ink token at about L 0.5, which reads at roughly 6:1 or better
on the tinted strip. The dot keeps the bright tag colour.

**The status bar** shows the state only: Ready, Running… 3s, Canceling…,
notices, Not connected, or "No connection" when nothing is selected. The
connection's mark and name move to the strip. The bar is 32px high, on
`--chrome` with a hairline on top. It is later the place for the
open-transaction indicator (`docs/backlog/open-transaction-indicator.md`).

**Editor tabs** sit in a segmented track: a `--muted` rounded rectangle
(radius 10px, padding 3px) holding the tabs. Each tab is 28px high with
radius 7px at 13.5px. The active tab is a raised white pill (`bg-background`,
`shadow-sm`, weight 500). Inactive tabs have muted text. The pin, close,
rename, context menu and middle-click behaviour is unchanged. The `+`, the
recently closed menu and the row details toggle stay where they are. The
row is 46px high, white, with a soft hairline under it.

**Result tabs** are chips: fully rounded, 26px high, statement labels in
mono at 12.5px. The active chip is tinted with the accent
(`bg-primary/10 text-primary`). Messages gets a `MessageSquare` icon
before its label. Pin and close behave as today.

**Editor.** JetBrains Mono at 14.5px, line height 1.6, ligatures off
(`font-variant-ligatures: none`), so `<>` and `>=` read as typed. The
gutter has no border and the same background as the editor. The current
line's number is dark, with no background band. The caret is the accent.
Lines get 12px of left padding (CodeMirror's default is 6px), so the
statement block has room inside. The block is drawn 2px taller at the top
and at the bottom, with radius 7px and a hairline ring. Run is the
`default` button variant, indigo; Stop stays `secondary`.

**Grid.** Rows 30px (from 24), header 44px (from 40), cells at 13px
mono, header names at 13px, types at 11px. Alternate rows get a faint
band, `--row-alt`, and so does their row-number cell, which must stay
opaque because cells scroll under it. The selected row keeps
`bg-primary/10`. The footer is 32px.

**Sidebar.** On `--chrome`. Connection rows are 34px high, and the
selected row is `bg-primary/10` with weight 500. Tree rows are 28px (from
24) at 13.5px.

**Bigger defaults.** Tailwind's `text-xs` goes from 12px to 13px app-wide,
so every small label, menu, dialog and toast grows together. `text-sm`
stays 14px. The explicit sizes above cover the rest.

**Light only.** `main.tsx` follows the system's dark mode today. The
redesign is light only, and themes come later as a setting (backlog). So
the app stops toggling `.dark` and sets `color-scheme: light`. The `.dark`
token block stays in `index.css`, untouched, for the themes work.

`oklch` mix of a red tag into the cool grey swings the hue through blue
and turns the strip lavender. The existing `color-mix(in oklch, …)` uses
in `setup.ts` and `ResultGrid.tsx` mix one colour with a neutral and are
fine; new mixes in this plan use `in_oklab`.

### letgo-packages: the title bar option

`wails/shim/window.go`'s `NewWindow` builds `WebviewWindowOptions` from a
let-go map, and it passes only title, size, URL and hidden. It gains one
option, `:mac-title-bar`, whose value names one of Wails' presets:

| Value | Preset |
|---|---|
| `:default` (or absent) | `application.MacTitleBarDefault` |
| `:hidden` | `application.MacTitleBarHidden` |
| `:hidden-inset` | `application.MacTitleBarHiddenInset` |
| `:hidden-inset-unified` | `application.MacTitleBarHiddenInsetUnified` |

It sets `o.Mac.TitleBar`. Any other value is an error, and
`NewWindow` returns `(*application.WebviewWindow, error)` for it, as `New`
already does for its own options. The value arrives through `ToGo`, which
turns a keyword into a string. Accept the name with or without a leading
`:` (`strings.TrimPrefix`), because it may arrive either way, as `opt`'s
keyword/string keys do. The option has no effect off macOS. Release:
merge, then tag `wails-v0.5.0` on the merge commit. The user has allowed
pushing, merging and tagging in letgo-packages for this plan.

### What does not change

- No element moves; the strip is new chrome and only takes over the
  connection name from the status bar.
- No behaviour changes: keys, menus, tab and result actions, Run and Stop
  logic, persistence.
- The dark tokens.

### Testing

- letgo-packages: `window_test.lg` creates a window with each preset and
  checks that a bad value throws. Server mode has no real title bar, so
  the look is a manual check on a Mac.
- Quel unit tests: `widths.test.ts` follows the new `CHAR_W`. There are
  no component unit tests in this repo (no testing-library), so the UI is
  covered by e2e.
- Quel e2e: tests that read the profile name from the status bar
  (`getByRole("contentinfo")`) read it from the strip
  (`getByRole("banner")`). New assertions cover the strip showing the
  selected profile and "Quel" with none selected.
- Visual: a Playwright screenshot of the server-mode app, checked against
  the prototype by eye.
- The native title bar on macOS (traffic light position against the 40px
  strip, dragging, fullscreen) is checked by hand on a Mac by the user.
